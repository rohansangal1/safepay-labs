# Security and research scope

This project runs locally against its own subjects. Nothing in it authorizes testing systems you don't own or aren't explicitly authorized to test. See [docs/SAFETY.md](docs/SAFETY.md).

## Reporting a vulnerability
- **In this project:** use GitHub private vulnerability reporting (Security → Advisories → Report a vulnerability). It must be enabled in repository settings; until then, contact the owner privately.
- **In third-party software found during research** (for example, an open-source shop): report it to that project's maintainers under their security policy first. Don't file it here publicly.

Never post real payment data, secret keys, raw HAR files or unpatched vulnerability details in public issues or pull requests.

## Disclosure
Findings stay private until a coordinated disclosure plan is agreed with the affected maintainer. A 90-day remediation window is our default proposal, negotiable rather than an automatic publication deadline.
